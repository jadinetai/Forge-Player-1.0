# Forge-Player-1.0
Tired of Youtube's algorithim giving you songs you don't listen too/like? Forge Player curates mixes  based on your music history and Youtube Likes. Create mixes from several different genres and customize your playlists with Takeout!
# Forge Player 0.45

Local-first YouTube music library for Windows. This extends v0.1; its original importer and HTML remain as `legacy.py` and `static/v01-reference.html` for comparison. The active app uses the new modules, not the legacy HTTP server. No paid service or Python package installation is required.

## Start

Double-click `START_FORGE_PLAYER.bat`, or run Python 3.11+:

```text
python forge.py serve --open
```

Open http://127.0.0.1:8766. This separate port preserves the original v0.1 server on 8765. Closing the browser does not stop the server. Stop its terminal with Ctrl+C when launched from a terminal. Only loopback connections are accepted.

## Playback and automatic playlists (0.45)

No extra package or firmware is required. Connect Google, then use **Detect artists & build playlists** once for an existing library. New likes imports also read YouTube music categories and broad genre topics. Local mixes are created automatically when evidence is available; unrecognized videos remain in Review. Takeout remains necessary for historical play counts and frequency-based Favorites, not playback.

Use **Play** beside any Library recording, or load a mix in Player. Play/pause, seek and timestamp controls come from the official YouTube player. **Automatically try matching uploads when one fails** is enabled by default. When an upload returns error 100/101/150, Forge tries up to three artist/title/duration/version-matched search candidates, shows the alternate uploader, and retains your original library entry. A search result is not proof of recording identity, so this never merges listening history. There is no promise that every song has an available matching alternative. Configuration errors and age checks do not trigger repeated searches.

**Find another upload** lets you choose among candidates yourself; **Play on YouTube** opens the current upload in your default Windows browser. A blocked embed cannot be repaired by hiding the video or extracting its audio. Browser-specific restrictions may remain even when metadata reports an upload as embeddable. The owner verified Death Grips directly in Opera and Avian through automatic alternate recovery.

Automatic topic genres are broad, sourced YouTube classifications with confidence labels. Manual corrections, including clearing genres, take priority. Multiple genres can create multiple memberships. The artist detector accepts explicit autogenerated distribution credits and title/channel agreement; unresolved performers remain unknown. API-derived display data is valid for 30 days and can be refreshed with the detection button.

Search is read-only and on demand. Current Google documentation gives search its own default 100-call daily bucket; Forge caps its local search ledger at 90 and reuses results within the browser session. These calls are shown separately from the shared 9,500-unit local budget for other operations. Project-wide actual quota can differ. No playlist is published to YouTube without a separate preview and approval.

## Your data and migration

The default database is `forge_player.sqlite3` beside the app. No original database was copied or modified during development. To upgrade an existing database, stop v0.1, make a copy into this folder, and point `--db` at the COPY:

```text
python forge.py --db my-library-copy.sqlite3 init
python forge.py --db my-library-copy.sqlite3 serve
```

Migration creates a timestamped SQLite backup before changing the schema. It preserves `tracks`, `listens`, `skips`, and `import_log`; links recordings to original video IDs; preserves manual favorite/emotional choices and imported likes. Schema version is 5. Migration exceptions roll back the transaction. Never open the upgraded DB with v0.1: restore the pre-upgrade `.bak` to a different filename and use that with v0.1 instead. Keep the upgraded database too; later edits are not present in the backup.

Automatic Favorites deliberately changes: default is five recorded starts within the last 90 days, with liked-songs inclusion OFF. Lifetime count is no longer a permanent qualification. Manual include/exclude survives this change. The slider has an explicit Apply locally action, range 1–50, and membership count. Nothing is published when it moves.

## Import and inspect

Use Library → Import Google Takeout, or:

```text
python forge.py import "C:\path\takeout-part1.zip" "C:\path\takeout-part2.zip"
python forge.py stats
python forge.py export --out playlists.csv
```

Supported files: watch-history.json / watch_history.json, equivalent HTML, likes.json, liked-videos.csv / likes.csv; ZIP parts and directories. Archives read only relevant YouTube entries; unrelated files are never extracted. JSON is preferred if matching HTML exists. The JSON parser is incremental, with 2 MiB per-record and 1 GiB per-file limits. ZIP expansion ratio and total relevant bytes are bounded. A rejected limit is reported, not silently bypassed. Likes JSON object wrappers are limited to 2 MiB; list-form likes and CSV stream.

Audit reports are stored in SQLite and shown in Library and Analytics. They include source content hashes, source names, scanned/parsed/new/duplicate/untimed/review counts and errors. A damaged file retains completed events and can be retried without repeating them. Only explicit timezone dates enter recent counts. Unknown localized HTML dates remain untimed; no dates or durations are invented.

Event identity uses original video ID + normalized timestamp + occurrence number within the source file, independent of source labels and archive names. Across overlapping files it keeps the maximum observed multiplicity. Identical starts at identical timestamps cannot be distinguished conclusively across exports. Untimed identical rows have the same uncertainty. Both cases appear in the audit; this is an explicit limitation, not proof of exact event identity. Existing v0.1 events are preserved even if they already contain duplicates.

## Curate

Playlists are stored definitions with name, color, order, archive status and manual/smart/hybrid type. A recording can belong to multiple playlists. Edit / curate changes performing artist separately from uploader, music status, detailed genre tags and per-playlist Always/Never overrides. Manual corrections persist across imports. Topic-channel artist normalization is labeled as a hint, not verified identity. Unknown artists stay unknown. Genre assignment is manual; YouTube categories do not prove musical subgenres.

Duplicate suggestions require an exact normalized artist/title match and human verification. No automatic fuzzy merge occurs. Merge/split keeps every video and listening event. Conflicting playlist exclusions block a merge. Undo restores the latest merge/split/bulk-review snapshot only if newer curation would not be overwritten. The model supports a single display artist string; a normalized multi-artist/alias graph is a remaining extension.

## Google login

1. Create/select a Google Cloud project. Enable **YouTube Data API v3**.
2. In Google Auth Platform, configure Branding and Audience. While Testing, add your own account under **Audience → Test users**.
3. Create a **Desktop app** OAuth client. Download its JSON from the creation view immediately; Google may stop offering the secret after navigation.
4. In Connections, give Forge the local JSON path. It is copied to `.private/google-client.json`, excluded from source packages and Git.
5. Click **Log In with Google**, then review the Google consent page in your default Windows browser. The first flow requests `youtube.readonly`, uses loopback callback, state validation and PKCE. No password or cookies are collected by Forge.
6. On return, verify the channel name and ID. **Import available likes** reads up to the API cap of 1,000. It does not fetch full watch history; use Takeout for that. Absent results are never treated as unlikes.

Tokens are encrypted with Windows user-bound DPAPI in `.private/google-token.dpapi`. There is no plaintext fallback; another Windows user cannot simply copy and use the encrypted token. API access tokens never reach frontend responses or access logs. The Desktop client configuration is a public-client registration, not a substitute for protecting user tokens. Testing-mode refresh tokens can expire after seven days; reconnect if needed.

If Google accepts sign-in but channel lookup reports `accessNotConfigured`, enable **YouTube Data API v3** in the same Cloud project as the Desktop client. Allow activation time, then start a fresh Log In; an old callback cannot be replayed. Refresh status in an already-open Forge tab after completing consent in the default browser.

New API videos use YouTube music-category/topic evidence; uncertain videos stay in music review. API titles/uploaders are separately cached with source and fetch time, and are displayed for at most 30 days; imported or manually edited titles remain independent. Public redistribution still needs a complete policy/retention review (see HANDOFF.md).

## Preview and publish

Enable playlist publishing separately; Google requests `youtube.force-ssl`. Select local playlists, select privacy for newly created playlists (PRIVATE default), and click Preview changes. The preview names the channel, lists exact additions and remote-only items kept, and estimates quota. Only Confirm account and publish approves that stored snapshot. Previewing and moving the Favorites slider do not mutate YouTube.

Publishing is add-only in this preview release. Removals are intentionally unavailable. Existing playlists are identified only by app-stored remote IDs, never by matching names; unrelated playlists are not adopted. Existing privacy is preserved. Each create/add estimates 50 quota units. Forge has a conservative 9,500-unit daily local cap resetting on Pacific dates; actual shared-project remaining quota must be checked in Cloud Console.

Each operation checkpoints before and after its request. Refreshing or closing the page pauses the browser-driven worker after the in-flight request; Resume continues the approved snapshot. Item failures are visible and finish as complete-with-errors. Quota exhaustion pauses. Successful writes are not repeated. A lost response may mean a write succeeded: Forge stops for reconciliation instead of retrying blindly. For an uncertain playlist creation, Details → Recover playlist ID verifies channel ownership and the unique Forge marker. For an uncertain item add, inspect YouTube and make a fresh preview if reconciliation cannot establish the result. Cancel does not undo writes already completed. New previews can retry known failed items.

No production playlist write was required for the automated tests. Check HANDOFF.md for actual live validation evidence.

## Disconnect and data controls

Connections → Disconnect and revoke calls Google's token revocation endpoint, removes the local token and cached API metadata/like observations, and cancels unfinished jobs. It does not delete Takeout history or manual curation. If revocation fails offline, credentials are retained so you can retry. You can also revoke at https://myaccount.google.com/permissions.

CSV export is available from Library. For complete local-data removal, stop Forge, back up what you want to keep, then remove its database, backups and `.private` folder yourself. Synced YouTube playlists remain in your account; remove those through YouTube. Do not include Takeout archives, databases, backups, logs or `.private` in public repositories.

## Tests

```text
python -m unittest discover -s tests -v
node tests/test_player.cjs
```

Tests use temporary synthetic data, mocked Google responses, a temporary loopback HTTP server, and a Windows DPAPI round-trip. They make no Google writes. For restricted environments, set TEMP/TMP to a writable directory and permit loopback networking for the HTTP tests.
